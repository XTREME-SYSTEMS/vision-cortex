## Summary
Build a unified Google Workspace connector service that validates and health-checks OAuth authorization across Drive, Calendar, Gmail, Sheets, Tasks, and Search Console, exposing them as Discover-layer data sources.

## Steps
- Define a GoogleConnector Base44 entity tracking each service (drive, calendar, gmail, sheets, tasks, searchConsole) with fields: service, status, scopes, tokenExpiry, lastHealthCheck, accountEmail.
- Store OAuth refresh tokens securely in Supabase (zero-credit store) keyed by service, never in Base44 entities.
- Implement a backend function that reads authorized scopes, refreshes access tokens as needed, and performs a lightweight read call per service (Drive files.list limit 1, Calendar calendarList, Gmail profile, Sheets metadata, Tasks tasklists, Search Console sites.list).
- Record per-service health status and expiry into the GoogleConnector entity on each run.
- Wire the connector into the Discover layer data-source registry so Understand/Predict/Act layers can query Google Workspace data.
- Add a Vercel Cron heartbeat to re-validate tokens hourly and auto-refresh before expiry.
- Emit a consolidated status report to CoreDocument for observability.

## Acceptance Criteria
connectGoogleWorkspace returns status 'connected' for all six services (drive, calendar, gmail, sheets, tasks, searchConsole), the GoogleConnector entity shows a recent lastHealthCheck with valid non-expired tokens for each, and each service returns a successful sample read call without auth errors.
