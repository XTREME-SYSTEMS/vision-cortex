## Summary
Build a unified Google Workspace connector health-check and sync orchestrator that validates OAuth authorization and normalizes data ingestion across Drive, Calendar, Gmail, Sheets, Tasks, and Search Console into the Discover layer.

## Steps
- Create a Base44 backend function `googleConnectorSync` (Deno/TypeScript) that accepts a list of Google services to validate and sync.
- For each service, retrieve stored OAuth credentials from Supabase and verify token validity; refresh expired tokens using the stored refresh_token.
- Perform a lightweight authorization probe per service (Drive: files.list limit 1; Calendar: calendarList.list; Gmail: users.getProfile; Sheets: spreadsheets metadata; Tasks: tasklists.list; Search Console: sites.list).
- Normalize each probe result into a ConnectorStatus entity ({service, authorized, scopes, lastChecked, error}) and upsert into Base44 entities.
- Ingest incremental data into the Discover layer: recent Drive docs metadata, upcoming Calendar events, unread Gmail summaries, Sheet ranges, open Tasks, and Search Console query performance.
- Write ingested records to Supabase (zero-credit store) and log the run into DeepRun execution logs.
- Register a Vercel Cron heartbeat to invoke `googleConnectorSync` on a recurring schedule for autonomous refresh.
- Emit a consolidated health report and surface any deauthorized services for re-consent.

## Acceptance Criteria
Invoking googleConnectorSync returns authorized=true for all six Google services (Drive, Calendar, Gmail, Sheets, Tasks, Search Console), ConnectorStatus entities are upserted with fresh lastChecked timestamps, incremental data lands in Supabase, a DeepRun log entry is created, and the Vercel Cron schedule successfully triggers subsequent runs without auth errors.
