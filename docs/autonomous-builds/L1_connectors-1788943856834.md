## Summary
Build a unified Google Workspace connector service that authorizes and health-checks Drive, Calendar, Gmail, Sheets, Tasks, and Search Console for the Discover layer.

## Steps
- Create a Base44 backend function `googleConnectorSync` in Deno/TypeScript that manages OAuth token lifecycle for all six Google services
- Store OAuth credentials and refresh tokens securely in Supabase (zero-credit external store) under a `google_connectors` table keyed by service
- Implement per-service scope validation: Drive (drive.readonly, drive.file), Calendar (calendar.events), Gmail (gmail.readonly, gmail.send), Sheets (spreadsheets), Tasks (tasks), Search Console (webmasters.readonly)
- Add token refresh logic that detects expiry and refreshes via Google OAuth2 endpoint, updating Supabase
- Implement a health-check probe that makes one lightweight authenticated call per service and records status/latency
- Persist connector state as a Base44 entity `GoogleConnectorStatus` so the Discover layer can query availability
- Wire the sync into Vercel Cron heartbeat to re-validate tokens periodically and alert on failures
- Follow technical standards: @/ imports, lucide-react icons for any status UI, default exports, small focused files

## Acceptance Criteria
All six services (Drive, Calendar, Gmail, Sheets, Tasks, Search Console) return a successful authenticated health-check; GoogleConnectorStatus entity shows status='connected' with valid non-expired tokens for each; the cron heartbeat re-validates without manual intervention and logs are visible in DeepRun.
