## Summary
Build a unified Google Workspace connector health-check and orchestration function that verifies and consolidates the authorized Drive, Calendar, Gmail, Sheets, Tasks, and Search Console connectors into the Discover layer's data plane.

## Steps
- Create a Base44 backend function `googleConnectorsSync` in Deno/TypeScript that reads stored OAuth tokens for each Google service from Supabase.
- For each connector (Drive, Calendar, Gmail, Sheets, Tasks, Search Console), issue a lightweight verification call: Drive files.list(limit 1), Calendar calendarList.list, Gmail users.getProfile, Sheets spreadsheets.get (probe sheet), Tasks tasklists.list, Search Console sites.list.
- Implement token refresh logic using the stored refresh_token when a 401 is returned, persisting the new access_token back to Supabase.
- Normalize each connector's status into a ConnectorHealth entity (service, status, scopes, last_checked, error) and upsert into Base44 entities.
- Register the connectors as Discover-layer data sources so the intelligence pipeline can query them (per Intelligence Gathering Protocol layer 1).
- Emit a consolidated summary result and log a DeepRun execution record for replayability.
- Wire the function into Vercel Cron heartbeat to re-validate connector health on a recurring schedule.

## Acceptance Criteria
Invoking googleConnectorsSync returns status 'connected' for all six services (Drive, Calendar, Gmail, Sheets, Tasks, Search Console) with valid non-expired tokens; a ConnectorHealth record is upserted per service with last_checked timestamp; expired tokens are auto-refreshed; and a DeepRun log entry is created. Any connector failure surfaces a clear error field rather than a silent failure.
