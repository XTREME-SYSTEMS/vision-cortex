## Summary
Build a unified Google Workspace connector service that verifies and persists OAuth authorization state for Drive, Calendar, Gmail, Sheets, Tasks, and Search Console into the Discover layer.

## Steps
- Define a GoogleConnector entity in Base44 with fields: service (enum: drive|calendar|gmail|sheets|tasks|search_console), status, scopes[], token_ref, last_verified_at, error_detail
- Register OAuth scopes for each of the six services in the Google Workspace integration config (drive.readonly, calendar.readonly, gmail.readonly, spreadsheets, tasks.readonly, webmasters.readonly)
- Implement the syncGoogleConnectors backend function to iterate each service, perform a lightweight health-check API call, and upsert the resulting status into GoogleConnector entities
- Store refresh/access token references securely via Supabase (zero-credit external store), never in Base44 entity plaintext
- Wire the connector health-check into a Vercel Cron heartbeat so connector status is re-verified on the autonomous loop
- Expose connector status to the Discover layer data sources registry so downstream Understand/Predict layers can consume Google-sourced signals
- Add error handling and re-auth prompts when any service returns 401/403, setting status=needs_reauth
- Emit a DeepRun log entry recording the sync outcome for replayability

## Acceptance Criteria
All six GoogleConnector entities (drive, calendar, gmail, sheets, tasks, search_console) exist with status=connected and last_verified_at within the last cron cycle; each health-check API call returns 200; token references are stored in Supabase not Base44 plaintext; a DeepRun log entry records the successful sync; and the Discover layer registry lists all six services as active data sources.
