## Summary
Build a unified Google Workspace connector health-check and token-management service that validates and refreshes OAuth access for Drive, Calendar, Gmail, Sheets, Tasks, and Search Console.

## Steps
- Create a Base44 backend function `googleConnectorManager` in Deno/TypeScript that centralizes OAuth token storage and refresh for all six Google services.
- Add a `GoogleConnector` Base44 entity (or Supabase table) with fields: service, status, scopes, access_token_expiry, refresh_token_ref, last_verified_at, error_message.
- For each service, implement a lightweight verification probe (Drive: files.list?pageSize=1, Calendar: calendarList.list, Gmail: users.getProfile, Sheets: spreadsheets metadata read, Tasks: tasklists.list, Search Console: sites.list).
- Implement automatic token refresh using the stored refresh_token when access_token is within 5 minutes of expiry; persist the new token securely.
- Return a consolidated health report per service (connected / degraded / expired / error) and write results to the GoogleConnector entity.
- Register a Vercel Cron heartbeat to invoke `googleConnectorManager` with action 'verify_all' every 30 minutes for autonomous monitoring.
- Emit a DeepRun log entry recording the verification outcome and any refresh actions for replayability.

## Acceptance Criteria
Invoking googleConnectorManager returns a report showing all six services (Drive, Calendar, Gmail, Sheets, Tasks, Search Console) with status 'connected', expired tokens are auto-refreshed without manual intervention, GoogleConnector entities reflect the latest last_verified_at timestamp, and the Vercel Cron heartbeat successfully triggers periodic verification with a corresponding DeepRun log entry.
