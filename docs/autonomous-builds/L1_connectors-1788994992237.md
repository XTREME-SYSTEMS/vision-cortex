## Summary
Build a unified Google Workspace connector service that validates and exposes authorized OAuth access to Drive, Calendar, Gmail, Sheets, Tasks, and Search Console for the Discover layer.

## Steps
- Create a Base44 backend function `googleWorkspaceConnector` in Deno/TypeScript that manages OAuth2 tokens for the six Google services
- Store and refresh OAuth credentials securely in Supabase (table `google_oauth_tokens`) keyed by service and account, with automatic token refresh on expiry
- Implement per-service health-check handlers: Drive (files.list), Calendar (calendarList.list), Gmail (users.getProfile), Sheets (spreadsheets metadata ping), Tasks (tasklists.list), Search Console (sites.list)
- Expose a unified `verify` action that pings all six services and returns a status map with scopes and last-refresh timestamps
- Register each connector as a Discover-layer data source in the system architecture registry (CoreDocument/architecture Data Sources section)
- Add error handling and structured logging to DeepRun execution logs for each connector call
- Emit a consolidated connectivity report entity in Base44 so the Council/Understand layer can consume Google service availability

## Acceptance Criteria
Calling googleWorkspaceConnector with action 'verify' returns HTTP 200 and a status map showing all six services (Drive, Calendar, Gmail, Sheets, Tasks, Search Console) as 'connected' with valid non-expired tokens; a connectivity report entity is persisted in Base44; and each connector appears as a registered Discover-layer data source with a successful health-check logged to DeepRun.
