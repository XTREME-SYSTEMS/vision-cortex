## Summary
Build a unified Google Workspace connector service that validates and health-checks the authorized Drive, Calendar, Gmail, Sheets, Tasks, and Search Console integrations for the Discover layer.

## Steps
- Create a Base44 backend function `googleConnectorHealth` in Deno/TypeScript that accepts a list of Google services to verify
- Load stored OAuth credentials/tokens for each Google Workspace service from Supabase secure store
- For each service (Drive, Calendar, Gmail, Sheets, Tasks, Search Console), perform a minimal read-only API probe (e.g., Drive files.list limit 1, Calendar calendarList, Gmail profile, Sheets metadata, Tasks tasklists, Search Console sites.list)
- Implement automatic token refresh using the stored refresh_token when a 401 is returned
- Normalize each probe result into a status object {service, connected, scopes, lastChecked, error}
- Persist connector status to a Base44 entity `ConnectorStatus` and write a DeepRun execution log entry
- Expose the aggregate health payload to the Discover layer so downstream state machines can gate on connector availability
- Add a Vercel cron heartbeat to invoke the health check on a recurring schedule for continuous monitoring

## Acceptance Criteria
Invoking googleConnectorHealth returns a status array where all six Google services (Drive, Calendar, Gmail, Sheets, Tasks, Search Console) report connected:true with valid scopes, expired tokens are auto-refreshed, results are persisted to the ConnectorStatus entity, and a DeepRun log entry is recorded.
