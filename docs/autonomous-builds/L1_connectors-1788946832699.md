## Summary
Build a unified Google Workspace connector service that validates and health-checks the authorized Drive, Calendar, Gmail, Sheets, Tasks, and Search Console integrations under the Discover layer.

## Steps
- Create a Base44 backend function `googleConnectorManager` in Deno/TypeScript that centralizes OAuth token retrieval and refresh for all six Google services.
- Store per-service connection metadata (scopes, token expiry, account email, last-verified timestamp) in a Supabase table `google_connections` for zero-credit access.
- Implement a `verifyConnection` routine that pings each service's lightweight endpoint (Drive files.list?pageSize=1, Calendar calendarList, Gmail profile, Sheets spreadsheets.get on a probe sheet, Tasks tasklists.list, Search Console sites.list) and records status.
- Add automatic token refresh using stored refresh tokens when expiry is within 5 minutes, updating Supabase on success.
- Expose a `healthReport` action returning connected/degraded/failed status per service for the Discover layer dashboard.
- Wire the connector into the Vercel Cron heartbeat to re-verify all connections every 30 minutes and log results to DeepRun.
- Emit failures as Base44 entity alerts so the Understand layer can react to lost connectivity.
- Follow technical standards: JavaScript/JSX conventions, @/ alias imports, lucide-react icons for any status UI.

## Acceptance Criteria
All six Google services (Drive, Calendar, Gmail, Sheets, Tasks, Search Console) return a 'connected' status via the healthReport action, tokens auto-refresh without manual intervention, connection metadata is persisted in the Supabase google_connections table, and the cron heartbeat logs a successful verification cycle to DeepRun every 30 minutes.
