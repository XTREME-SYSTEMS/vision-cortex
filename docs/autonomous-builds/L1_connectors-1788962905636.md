## Summary
Build a unified Google Workspace connector health-check and orchestration layer that verifies and exposes the authorized Drive, Calendar, Gmail, Sheets, Tasks, and Search Console connectors to the Discover layer.

## Steps
- Create a Base44 backend function `googleConnectorHub` (Deno/TypeScript) that reads stored OAuth credentials for the Google Workspace integration from Supabase secrets store.
- For each service (Drive, Calendar, Gmail, Sheets, Tasks, Search Console), implement a lightweight ping method that issues a minimal read-only API call (e.g., Drive files.list?pageSize=1, Calendar calendarList, Gmail profile, Sheets metadata, Tasks tasklists.list, Search Console sites.list).
- Normalize each response into a ConnectorStatus record { service, connected, scopes, lastChecked, error } and upsert into a Base44 `ConnectorStatus` entity.
- Implement automatic token refresh using the stored refresh_token when a 401 is returned, and persist the new access_token.
- Expose a single `getConnectorHealth` action returning the aggregated status array for the Discover layer to consume.
- Register the function on Vercel Cron heartbeat to re-validate all connectors every 6 hours and log results to DeepRun.
- Add error alerting: if any connector reports connected=false, write an IntelFeed/system alert entry.
- Follow technical standards: @/ imports, default exports, lucide-react icons for any status UI badge component.

## Acceptance Criteria
Invoking googleConnectorHub returns a status array with all six services (Drive, Calendar, Gmail, Sheets, Tasks, Search Console) reporting connected=true with valid scopes; ConnectorStatus entities are upserted with fresh lastChecked timestamps; expired tokens auto-refresh without manual intervention; and the Vercel Cron re-check logs a successful DeepRun entry every 6 hours.
