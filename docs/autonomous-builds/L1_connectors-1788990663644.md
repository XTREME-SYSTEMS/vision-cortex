## Summary
Build a unified Google Workspace connector health-check and sync orchestrator that validates and refreshes the authorized Drive, Calendar, Gmail, Sheets, Tasks, and Search Console connections.

## Steps
- Create a Base44 backend function `google_connector_sync` in Deno/TypeScript that iterates over the six authorized Google services (Drive, Calendar, Gmail, Sheets, Tasks, Search Console)
- Load stored OAuth credentials for each service from the Supabase `google_credentials` table using the zero-credit external data store
- For each service, perform a lightweight authenticated ping (Drive: files.list limit 1; Calendar: calendarList.list; Gmail: users.getProfile; Sheets: spreadsheets read on a canary sheet; Tasks: tasklists.list; Search Console: sites.list) to validate the token
- If a token is expired, use the refresh_token to obtain a new access_token via the Google OAuth token endpoint and persist it back to Supabase
- Record each connector's status, latency, scopes, and last_checked timestamp into a Base44 `ConnectorStatus` entity
- Register the sync as a DEEP state machine (DeepSpec) so the Discover layer can invoke it deterministically and log runs to DeepRun
- Add a Vercel Cron heartbeat entry to invoke `google_connector_sync` on a recurring schedule for autonomous re-validation
- Return a consolidated report of healthy/degraded/failed connectors
- Follow technical standards: @/ import alias, lucide-react icons for any status UI, small focused components under 50 lines

## Acceptance Criteria
Invoking google_connector_sync returns a report where all six Google services (Drive, Calendar, Gmail, Sheets, Tasks, Search Console) report status 'healthy' with valid non-expired tokens, a ConnectorStatus entity is written per service with a recent last_checked timestamp, expired tokens are automatically refreshed and persisted to Supabase, and the DeepRun log shows a successful deterministic execution triggered by the Vercel Cron heartbeat.
