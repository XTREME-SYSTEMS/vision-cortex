## Summary
Build a unified Google Workspace connector service that verifies and manages OAuth access to Drive, Calendar, Gmail, Sheets, Tasks, and Search Console for the Discover layer.

## Steps
- Create a backend function `googleConnectorManager` in the Base44 Deno/TypeScript backend that centralizes Google Workspace OAuth token storage and refresh
- Store connector credentials and scopes in a Supabase table `google_connectors` (columns: service, status, scopes, token_expiry, last_verified) for zero-credit operations
- Implement OAuth refresh-token flow with automatic renewal for each of the six services (Drive, Calendar, Gmail, Sheets, Tasks, Search Console)
- Add a health-check routine that pings each Google API endpoint and records connection status and latency
- Expose a `verifyConnections` action that returns per-service authorization state to the Discover layer intelligence pipeline
- Register the connector service as a data source in the Discover layer config alongside Cloud Browser and Microlink.io
- Wire a Vercel Cron heartbeat to run `verifyConnections` every 6 hours and log results to DeepRun
- Emit a DeepSpec-compatible validated status object so downstream Understand/Predict layers can consume connector availability

## Acceptance Criteria
Calling googleConnectorManager with action=verifyConnections returns status=connected for all six services (Drive, Calendar, Gmail, Sheets, Tasks, Search Console), tokens auto-refresh before expiry, the google_connectors Supabase table reflects last_verified timestamps within the last cron cycle, and the Discover layer can list all six as active data sources.
