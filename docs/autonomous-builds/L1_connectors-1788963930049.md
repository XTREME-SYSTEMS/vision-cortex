## Summary
Build a unified Google Workspace connector health-check and token-refresh service that verifies and maintains authorized access to Drive, Calendar, Gmail, Sheets, Tasks, and Search Console.

## Steps
- Create a Base44 backend function `googleConnectorHealthCheck` in Deno/TypeScript that enumerates all six authorized Google scopes
- Load stored OAuth credentials (access + refresh tokens) from the Supabase `google_connectors` table for zero-credit reads
- For each service (Drive, Calendar, Gmail, Sheets, Tasks, Search Console) issue a lightweight authenticated probe call (e.g., Drive about.get, Calendar calendarList.list, Gmail profile.get, Sheets spreadsheets metadata ping, Tasks tasklists.list, Search Console sites.list)
- Detect expired/invalid access tokens and perform automatic refresh via the Google OAuth token endpoint using stored refresh tokens
- Persist refreshed tokens and per-connector status (connected/degraded/failed, last_checked, latency_ms) back into Supabase
- Emit a consolidated ConnectorStatus record into Base44 entities for the Discover layer to consume
- Register a Vercel Cron heartbeat to invoke this function on a schedule to keep connectors warm and tokens valid
- Log the run to DeepRun with a replayable DEEP state entry for audit

## Acceptance Criteria
Invoking googleConnectorHealthCheck returns a status object where all six connectors (Drive, Calendar, Gmail, Sheets, Tasks, Search Console) report status 'connected' with a fresh access token, expired tokens are auto-refreshed and persisted to Supabase, a ConnectorStatus entity is written, the Vercel cron heartbeat is scheduled, and the run is logged to DeepRun.
