## Summary
Build a unified Google Workspace connector health-check and orchestration function that validates and registers all six authorized Google services (Drive, Calendar, Gmail, Sheets, Tasks, Search Console) into the Discover layer's data plane.

## Steps
- Create a Base44 backend function `googleConnectorOrchestrator` in Deno/TypeScript that centralizes OAuth token retrieval for the Google Workspace integration
- For each service (Drive, Calendar, Gmail, Sheets, Tasks, Search Console), implement a lightweight ping call against its API using the shared OAuth credentials to verify authorization scope and connectivity
- Persist connector status records to a Supabase table `google_connectors` with fields: service, status, scopes, last_checked, error (zero-credit external store)
- Register successful connectors as Discover-layer data sources so the Intelligence Gathering Protocol can enumerate them
- Emit a consolidated health report entity and log the run to DeepRun for replayability
- Add a Vercel Cron heartbeat entry to re-run the health check periodically and auto-flag degraded connectors
- Expose the connector registry via @/ aliased helper so frontend React components can display connection status using lucide-react icons

## Acceptance Criteria
All six Google services return status 'connected' in the Supabase `google_connectors` table with valid scopes and a recent last_checked timestamp; a DeepRun log entry exists for the orchestration; the Discover layer enumerates all six as active data sources; and re-running the function is idempotent, updating rather than duplicating status records.
