## Summary
Build a unified Google Workspace connector service that authorizes, health-checks, and normalizes access to Drive, Calendar, Gmail, Sheets, Tasks, and Search Console for the Discover layer.

## Steps
- Create a Base44 backend function that stores and refreshes OAuth2 tokens for the Google Workspace account, using a Supabase table (google_connections) to persist encrypted refresh tokens per service scope
- Define the required OAuth scopes: drive.readonly, calendar.readonly, gmail.readonly, spreadsheets, tasks, webmasters.readonly
- Implement a token refresh routine that exchanges refresh tokens for access tokens and caches them with expiry timestamps to avoid rate limits
- Add per-service health-check probes: Drive files.list, Calendar calendarList.list, Gmail profile.get, Sheets spreadsheets.get (ping sheet), Tasks tasklists.list, Search Console sites.list
- Normalize each probe result into a standard ConnectorStatus record {service, connected, scopes, lastChecked, error} and upsert into Supabase connector_status table
- Expose a single callable action ('status'|'refresh'|'probe') so the Discover layer can query connector readiness before running intelligence loops
- Wire the health-check into Vercel Cron heartbeat to periodically revalidate all six connectors and flag degraded ones
- Log all probe runs to DeepRun for replayability and surface a consolidated readiness summary

## Acceptance Criteria
Invoking googleWorkspaceConnector with action 'probe' returns connected:true for all six services (Drive, Calendar, Gmail, Sheets, Tasks, Search Console) with valid scopes and no errors, connector_status rows are upserted in Supabase, tokens auto-refresh before expiry, and the cron heartbeat records a successful DeepRun entry.
