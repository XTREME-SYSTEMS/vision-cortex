## Summary
Build a unified Google Workspace connector service that validates and health-checks the authorized Drive, Calendar, Gmail, Sheets, Tasks, and Search Console connections for the Discover layer.

## Steps
- Create a Base44 backend function 'googleConnectorHealth' in Deno/TypeScript that accepts a list of Google services to verify
- Load stored OAuth credentials/tokens for the connected Google Workspace account from Supabase secure store
- For each service (Drive, Calendar, Gmail, Sheets, Tasks, Search Console), perform a lightweight authenticated ping (e.g., Drive files.list limit=1, Calendar calendarList.list, Gmail getProfile, Sheets spreadsheets.get on a probe sheet, Tasks tasklists.list, Search Console sites.list)
- Detect expired tokens and trigger OAuth refresh using the refresh_token; persist refreshed access tokens back to Supabase
- Record each connector's status, scopes, latency, and last-verified timestamp into a Base44 'ConnectorStatus' entity
- Emit a consolidated health report and register the connectors as available Discover-layer data sources in the system registry
- Add a Vercel Cron heartbeat entry to re-run googleConnectorHealth periodically for zero-credit monitoring

## Acceptance Criteria
Invoking googleConnectorHealth returns status=connected for all six Google services with valid (non-expired) tokens, a ConnectorStatus entity row exists per service with a recent last-verified timestamp, expired tokens are auto-refreshed, and the connectors appear as registered Discover-layer data sources.
