## Summary
Build a unified Google Workspace connector health-check and orchestration function that verifies and exposes the authorized Drive, Calendar, Gmail, Sheets, Tasks, and Search Console connectors to the Discover layer.

## Steps
- Create a Base44 backend function `googleConnectorsSync` in Deno/TypeScript that reads stored OAuth credentials for the Google Workspace account
- For each connector (Drive, Calendar, Gmail, Sheets, Tasks, Search Console), perform a lightweight authenticated ping to validate the access token and refresh it if expired
- Persist connector status (connected/degraded/failed, last_checked, scopes) to a Base44 `ConnectorStatus` entity and mirror to Supabase for zero-credit reads
- Expose normalized read helpers per connector (list Drive files, upcoming Calendar events, recent Gmail threads, Sheets ranges, Tasks lists, Search Console query performance) callable by the Discover layer
- Register the function on Vercel Cron heartbeat to re-validate tokens every 6 hours and auto-refresh before expiry
- Emit an IntelFeed signal when any connector transitions to degraded/failed so the Council is notified
- Follow coding standards: @/ imports, default exports, lucide-react icons for any status UI panel

## Acceptance Criteria
Calling googleConnectorsSync returns a status object listing all six Google connectors as 'connected' with valid non-expired tokens, ConnectorStatus entities are persisted and mirrored to Supabase, the Discover layer can successfully invoke each connector's read helper, and the Vercel cron re-validation runs without token-refresh errors.
