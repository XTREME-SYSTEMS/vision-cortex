## Summary
Build a unified Google Workspace connector service that verifies and persists OAuth authorization for Drive, Calendar, Gmail, Sheets, Tasks, and Search Console into the Discover layer.

## Steps
- Create a Base44 backend function `googleConnectorSync` (Deno/TypeScript) that centralizes Google Workspace API access using stored OAuth credentials.
- Define a `GoogleConnector` Base44 entity to persist connection state per service (service name, scopes, status, tokenRef, lastVerifiedAt, expiresAt).
- For each of the six services (Drive, Calendar, Gmail, Sheets, Tasks, Search Console), perform a lightweight authenticated health-check call (e.g., Drive about.get, Calendar calendarList.list, Gmail profile.get, Sheets spreadsheets metadata ping, Tasks tasklists.list, Search Console sites.list).
- Store returned scopes and authorization status in the `GoogleConnector` entity; mark each service authorized/failed with timestamp.
- Implement token refresh logic using the refresh_token when access tokens are expired, updating the persisted tokenRef.
- Wire the connector into the Discover layer data sources so intelligence gathering can query Google services with zero extra auth friction.
- Register a Vercel Cron heartbeat entry to re-verify connectors periodically and re-run refresh when tokens near expiry.
- Emit a DeepRun execution log recording the sync result for replayability and auditing.

## Acceptance Criteria
All six Google services (Drive, Calendar, Gmail, Sheets, Tasks, Search Console) return successful authenticated health-check responses; a `GoogleConnector` entity row exists per service with status=authorized, valid scopes, and a recent lastVerifiedAt; token refresh succeeds on expiry; and a DeepRun log entry records the successful sync.
