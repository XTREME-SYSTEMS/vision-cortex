## Summary
Build a unified Google Workspace connector service that validates and health-checks the authorized Drive, Calendar, Gmail, Sheets, Tasks, and Search Console integrations feeding the Discover layer.

## Steps
- Create a Base44 backend function `googleConnectorSync` (Deno/TypeScript) that centralizes OAuth token retrieval and refresh for all six Google services
- Store connector metadata (service name, scopes, token status, last sync timestamp) in a Supabase table `google_connectors` for zero-credit status tracking
- Implement per-service health-check calls: Drive files.list, Calendar calendarList.list, Gmail users.getProfile, Sheets spreadsheets.get (probe), Tasks tasklists.list, Search Console sites.list
- Normalize each service result into a standard connector status object {service, connected, scopes, error, lastChecked} and persist to Supabase
- Wire the connector into the Discover layer data-source registry so intelligence gathering can query available Google services
- Register a Vercel Cron heartbeat to invoke `googleConnectorSync` on an interval to auto-refresh tokens and re-validate connectivity
- Log each sync run to DeepRun for replayable execution auditing
- Emit a consolidated health report and surface failures to the Council/Understand layer

## Acceptance Criteria
All six Google services (Drive, Calendar, Gmail, Sheets, Tasks, Search Console) return connected:true with valid non-expired tokens in the google_connectors Supabase table, the health-check probe succeeds for each without auth errors, the cron heartbeat runs on schedule refreshing tokens, and a DeepRun log entry is produced for each sync confirming the Discover layer can enumerate all available Google data sources.
