## Summary
Build a unified Google Workspace connector service that verifies and health-checks the authorized Drive, Calendar, Gmail, Sheets, Tasks, and Search Console integrations, exposing them as Discover-layer data sources.

## Steps
- Create a Base44 backend function `googleConnectorManager` (Deno/TypeScript) that centralizes OAuth token handling and per-service client instantiation for Drive, Calendar, Gmail, Sheets, Tasks, and Search Console.
- Store and refresh OAuth credentials securely via Supabase (zero-credit external store), including access_token, refresh_token, scopes, and expiry per service.
- Implement a health-check routine that pings a lightweight read endpoint for each of the six services (e.g., Drive files.list limit 1, Calendar calendarList, Gmail profile, Sheets metadata, Tasks tasklists, Search Console sites.list) and records status.
- Register each connected service as a Discover-layer Data Source entity so the Intelligence Gathering Protocol can consume them.
- Persist a DeepRun log entry capturing connector status, latency, and scope validation for replayability.
- Expose a `status` action returning per-service connected/degraded/failed state and a consolidated boolean `allConnected`.
- Add token-refresh error handling and alerting when any scope is revoked or expired.

## Acceptance Criteria
Invoking googleConnectorManager with action=status returns allConnected=true and each of the six services (drive, calendar, gmail, sheets, tasks, searchConsole) reports status='connected' with a successful health-check ping under 2s; a DeepRun log entry is persisted and each service is registered as a Discover-layer Data Source entity.
