## Summary
Build a unified Google Workspace connector service that verifies and manages OAuth access to Drive, Calendar, Gmail, Sheets, Tasks, and Search Console for the Discover layer.

## Steps
- Create a Base44 backend function `googleWorkspaceConnector` in Deno/TypeScript that centralizes OAuth token handling for all Google services
- Store and refresh OAuth credentials securely in Supabase (table `google_oauth_tokens` with scopes, access_token, refresh_token, expiry per service)
- Implement per-service health-check probes: Drive (files.list), Calendar (calendarList.list), Gmail (users.getProfile), Sheets (spreadsheets.get on a test sheet), Tasks (tasklists.list), Search Console (sites.list)
- Add automatic token refresh using stored refresh_token when access_token is expired
- Expose a `verify` action returning connection status per service and a `refresh` action to force token renewal
- Register the connector as a Discover-layer data source and log verification results to DeepRun
- Add error handling with retry/backoff and structured status output for the Council layer to consume

## Acceptance Criteria
Invoking googleWorkspaceConnector with action 'verify' returns status 'connected' for all six services (Drive, Calendar, Gmail, Sheets, Tasks, Search Console), tokens auto-refresh when expired, credentials persist in Supabase, and a DeepRun log entry records the successful verification.
