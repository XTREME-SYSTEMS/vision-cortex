## Summary
Build a unified Google Workspace connector health-check and token-refresh service that verifies and maintains authorized access to Drive, Calendar, Gmail, Sheets, Tasks, and Search Console.

## Steps
- Create a Base44 backend function `googleConnectorManager` (Deno/TypeScript) that centralizes OAuth token handling for all six Google services.
- Store and retrieve OAuth refresh tokens and scopes from Supabase table `google_connectors` (columns: service, access_token, refresh_token, scope, expires_at, status, last_checked).
- Implement a per-service verification call: Drive files.list, Calendar calendarList.list, Gmail users.getProfile, Sheets spreadsheets metadata, Tasks tasklists.list, Search Console sites.list — each with minimal quota impact.
- Add automatic token refresh: when expires_at is near or a 401 is returned, exchange the refresh_token at Google's OAuth token endpoint and persist the new access_token/expires_at.
- Update each connector's `status` field to `connected`, `degraded`, or `error` with a diagnostic message, and log results to DeepRun.
- Register a Vercel Cron heartbeat to invoke `googleConnectorManager` on a schedule (e.g. every 30 min) to keep tokens warm and detect gaps proactively.
- Expose a summary response listing all six connectors with their live status for the Discover layer to consume.

## Acceptance Criteria
Invoking googleConnectorManager returns a status object where all six services (Drive, Calendar, Gmail, Sheets, Tasks, Search Console) report status 'connected'; expired tokens are auto-refreshed and persisted to Supabase; the Vercel Cron heartbeat runs on schedule and DeepRun logs show successful verification with no unresolved 'error' states.
