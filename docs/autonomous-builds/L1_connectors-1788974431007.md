## Summary
Build a unified Google Workspace connector health-check and token-refresh service that verifies and maintains the six authorized OAuth connections (Drive, Calendar, Gmail, Sheets, Tasks, Search Console).

## Steps
- Create a Base44 backend function `googleConnectorManager` (Deno/TypeScript) that centralizes OAuth token handling for all six Google scopes.
- Define a `GoogleConnector` Supabase table (service, scope, access_token, refresh_token, expires_at, status, last_checked) for zero-credit token state storage.
- Implement scope registry mapping each service to its required OAuth scope (drive.readonly/file, calendar, gmail.readonly, spreadsheets, tasks, webmasters.readonly).
- For each connector, call a lightweight verification endpoint (Drive about.get, Calendar calendarList.list, Gmail profile.get, Sheets ping, Tasks tasklists.list, Search Console sites.list) to confirm liveness.
- Add automatic token refresh: when expires_at is within 5 minutes, exchange refresh_token via Google OAuth token endpoint and persist new access_token.
- Register a Vercel Cron heartbeat to invoke `googleConnectorManager` every 30 minutes to keep tokens fresh and update status.
- Emit a consolidated status object per service (connected/degraded/expired) and log results to DeepRun for replayability.
- Surface connector status in the Discover layer so downstream intelligence gathering can rely on live Google Workspace access.

## Acceptance Criteria
Invoking googleConnectorManager returns status 'connected' for all six services (Drive, Calendar, Gmail, Sheets, Tasks, Search Console), the GoogleConnector table shows non-expired tokens with recent last_checked timestamps, the Vercel Cron heartbeat successfully refreshes tokens before expiry, and each run is logged to DeepRun.
