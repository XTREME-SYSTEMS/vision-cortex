## Summary
Build a unified Google Workspace connector health-check and orchestration function that validates and registers all authorized core infrastructure connectors (Drive, Calendar, Gmail, Sheets, Tasks, Search Console) into the Discover layer data plane.

## Steps
- Create a Base44 backend function 'verifyGoogleConnectors' in Deno/TypeScript that iterates over each authorized Google service
- For each connector (drive, calendar, gmail, sheets, tasks, searchConsole), invoke a lightweight read-only probe (e.g., Drive files.list limit 1, Calendar calendarList, Gmail profile, Sheets metadata, Tasks tasklists.list, Search Console sites.list) to confirm OAuth scopes and token validity
- Persist connector status into a Supabase 'connector_registry' table with fields: service, status, scopes, last_checked, error
- Register healthy connectors as active Discover-layer data sources referenced by the Intelligence Gathering Protocol
- Emit a consolidated health report and store it in CoreDocument ecosystem for system knowledge
- Wire the function into Vercel Cron heartbeat for periodic re-validation and token-refresh handling
- Surface any failing connector with actionable re-auth link in the report

## Acceptance Criteria
All six Google connectors (Drive, Calendar, Gmail, Sheets, Tasks, Search Console) return status 'active' in the Supabase connector_registry with valid scopes and recent last_checked timestamps, a consolidated health report is persisted to CoreDocument, and the cron re-validation runs without errors while flagging any expired tokens with a re-auth link.
