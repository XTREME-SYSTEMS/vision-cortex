## Summary
Build a unified Google Workspace connector service that validates and health-checks the authorized Drive, Calendar, Gmail, Sheets, Tasks, and Search Console integrations, persisting their status for the Discover layer.

## Steps
- Create a Base44 backend function `googleConnectorHealth` in Deno/TypeScript that reads stored OAuth tokens for the Google Workspace integration.
- For each service (Drive, Calendar, Gmail, Sheets, Tasks, Search Console), perform a lightweight authenticated probe call (e.g., Drive files.list?pageSize=1, Calendar calendarList.list, Gmail users.getProfile, Sheets spreadsheets metadata, Tasks tasklists.list, Search Console sites.list).
- Handle token refresh via the Google OAuth refresh_token flow when a probe returns 401, and persist the refreshed access token.
- Write a `ConnectorStatus` record per service into a Base44 entity capturing {service, connected, scopes, lastCheckedAt, latencyMs, error}.
- Expose an aggregated response summarizing overall connector health and any services needing re-authorization.
- Register a Vercel Cron heartbeat entry to invoke `googleConnectorHealth` on a recurring interval so the Discover layer always has fresh connector state.
- Follow technical standards: @/ import alias, lucide-react icons if any UI status widget is added, small focused files.

## Acceptance Criteria
Invoking googleConnectorHealth returns a JSON object with per-service status objects for Drive, Calendar, Gmail, Sheets, Tasks, and Search Console; each authorized service reports connected:true with a non-null lastCheckedAt and measured latency; expired tokens are auto-refreshed; ConnectorStatus entities are persisted and the cron heartbeat is registered and firing on schedule.
