## Summary
Build a unified Google Workspace connector service that validates and health-checks the authorized Drive, Calendar, Gmail, Sheets, Tasks, and Search Console connections and exposes them to the Discover layer.

## Steps
- Create a Base44 backend function `googleConnectorHealth` in Deno/TypeScript that reads stored OAuth credentials for each Google service from Supabase.
- For each connector (Drive, Calendar, Gmail, Sheets, Tasks, Search Console), perform a lightweight read call to confirm valid scopes and non-expired tokens.
- Implement automatic token refresh using the refresh_token when an access token is expired, persisting the new token back to Supabase.
- Normalize each service result into a status object {service, connected, scopes, lastChecked, error} and upsert into a `ConnectorStatus` Base44 entity.
- Register the connectors as Discover-layer data sources so the intelligence pipeline can pull from Search Console (SEO), Drive (docs), and Gmail/Calendar/Tasks (signals).
- Add a Vercel cron trigger to invoke `googleConnectorHealth` on the autonomous heartbeat to keep status fresh.
- Log the run to DeepRun for replayability and emit a summary of connected vs failing services.
- Follow coding standards: @/ imports, lucide-react icons for any status UI, small focused files.

## Acceptance Criteria
Invoking googleConnectorHealth returns a 200 with a status array covering all six Google services each marked connected:true with valid scopes; ConnectorStatus entities are upserted with fresh lastChecked timestamps; expired tokens are auto-refreshed; the run is logged to DeepRun and the cron heartbeat re-runs the check on schedule.
