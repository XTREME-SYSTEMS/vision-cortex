## Summary
Build a unified Google Workspace connector service that verifies and manages authorized OAuth connections to Drive, Calendar, Gmail, Sheets, Tasks, and Search Console within the Discover layer.

## Steps
- Create a Base44 backend function `googleWorkspaceConnector` in Deno/TypeScript that centralizes OAuth token handling for all six Google services
- Store OAuth credentials and refresh tokens securely in Supabase table `google_connections` (service, access_token, refresh_token, expires_at, scopes, status)
- Implement token refresh logic that auto-renews expired access tokens using stored refresh tokens before each service call
- Add per-service health-check probes: Drive files.list, Calendar calendarList.list, Gmail users.getProfile, Sheets spreadsheets.get, Tasks tasklists.list, Search Console sites.list
- Expose a `verify` action that returns connection status for each of the six services and persists results to Supabase
- Register the connector as a Discover-layer data source so intelligence loops can invoke authorized reads
- Add error handling and status flags (connected/degraded/failed) with structured logging to DeepRun execution logs
- Use @/ alias imports, keep helpers in small focused files, and expose the function as default export

## Acceptance Criteria
Invoking googleWorkspaceConnector with action=verify returns status 'connected' for all six services (Drive, Calendar, Gmail, Sheets, Tasks, Search Console), each health-check probe succeeds with a valid API response, refreshed tokens are persisted in the Supabase google_connections table, and connection statuses are logged to DeepRun with no failed services.
