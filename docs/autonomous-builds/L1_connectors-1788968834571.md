## Summary
Build a unified Google Workspace connector service that validates and health-checks the authorized Drive, Calendar, Gmail, Sheets, Tasks, and Search Console integrations for the Discover layer.

## Steps
- Create a Base44 backend function `googleConnectorHealthcheck` that reads stored OAuth credentials for each Google service
- Implement per-service token validation: refresh access tokens via Google OAuth2 endpoint and confirm scopes (drive.readonly, calendar, gmail.readonly, spreadsheets, tasks, webmasters.readonly)
- For each service, issue a minimal probe call (Drive: files.list limit 1; Calendar: calendarList.list; Gmail: users.getProfile; Sheets: spreadsheets metadata ping; Tasks: tasklists.list; Search Console: sites.list) and capture status
- Persist a `ConnectorStatus` entity record per service with fields: service, connected(bool), scopes, lastChecked, latencyMs, error
- Register the connector map in the Discover layer data-source registry so downstream DEEP state machines can invoke them
- Add a Vercel cron heartbeat entry to re-run the healthcheck every 6 hours and flag any degraded connector
- Emit a consolidated summary document to CoreDocument reflecting live connector availability

## Acceptance Criteria
All six Google services (Drive, Calendar, Gmail, Sheets, Tasks, Search Console) return connected=true with valid refreshed tokens, each probe call succeeds under 2000ms, a ConnectorStatus record exists per service with lastChecked within the current run, and the cron heartbeat is scheduled and logs successful re-validation.
