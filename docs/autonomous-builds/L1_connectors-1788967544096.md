## Summary
Build a unified Google Workspace connector service that verifies and health-checks the authorized Drive, Calendar, Gmail, Sheets, Tasks, and Search Console integrations, exposing them to the Discover layer.

## Steps
- Create a Base44 backend function `googleConnectorManager` that centralizes OAuth token handling and per-service client instantiation for Drive, Calendar, Gmail, Sheets, Tasks, and Search Console
- Store and refresh OAuth credentials securely via Supabase (zero-credit external store), including automatic token refresh when access tokens expire
- Implement a `verifyConnections` action that performs a lightweight read call against each service (e.g., Drive files.list limit 1, Calendar calendarList, Gmail profile, Sheets metadata, Tasks tasklists, Search Console sites.list) and records status
- Persist connection health results to a Base44 entity `IntegrationStatus` with fields service, connected, lastChecked, scopes, error
- Expose normalized read adapters so the Discover layer can pull data from each Google service through a single interface
- Add a Vercel Cron heartbeat entry to invoke `googleConnectorManager` with action `verifyConnections` on a recurring schedule
- Emit an alert/log to DeepRun when any service reports disconnected or scope-insufficient status

## Acceptance Criteria
Invoking googleConnectorManager with action verifyConnections returns connected:true for all six services (Drive, Calendar, Gmail, Sheets, Tasks, Search Console), IntegrationStatus entities are populated with recent lastChecked timestamps, token refresh succeeds without manual re-auth, and the cron heartbeat runs the check on schedule with failures logged to DeepRun.
