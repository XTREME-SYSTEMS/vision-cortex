## Summary
Build a unified Google Workspace connector service that verifies and manages OAuth-authorized access to Drive, Calendar, Gmail, Sheets, Tasks, and Search Console within the Discover layer.

## Steps
- Create a Base44 backend function `googleConnectorManager` (Deno/TypeScript) that centralizes OAuth token retrieval, refresh, and per-service client instantiation.
- Store and read Google OAuth credentials (access_token, refresh_token, scopes, expiry) from a Supabase table `google_connections` for zero-credit persistence.
- Implement token refresh logic that auto-renews expired access tokens using the stored refresh_token and Google's token endpoint.
- Add per-service health-check probes: Drive (files.list limit 1), Calendar (calendarList.list), Gmail (users.getProfile), Sheets (spreadsheets metadata get), Tasks (tasklists.list), Search Console (sites.list).
- Return a normalized connector status report `{ service, connected, scopes, lastChecked, error }` for each of the six services.
- Register the connector status output into the Discover layer data sources and log a DeepRun execution record for replayability.
- Expose a `mode` argument so the function can run in `verify` (health checks only) or `refresh` (force token renewal) mode.
- Handle and log missing/insufficient scopes with actionable remediation messages.

## Acceptance Criteria
Invoking googleConnectorManager in verify mode returns connected:true for all six services (Drive, Calendar, Gmail, Sheets, Tasks, Search Console) with valid non-expired tokens, a DeepRun log entry is persisted, and the google_connections Supabase table reflects current token expiry; expired tokens are transparently refreshed and any missing scope produces a clear remediation error.
