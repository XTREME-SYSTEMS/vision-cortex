## Summary
Build a unified Google Workspace connector service that verifies and manages OAuth authorization for Drive, Calendar, Gmail, Sheets, Tasks, and Search Console into the Discover layer.

## Steps
- Create a Base44 backend function `googleConnectorManager` in Deno/TypeScript that centralizes OAuth token handling for all six Google services
- Define a Supabase table `google_connectors` (service_name, oauth_scope, access_token, refresh_token, token_expiry, status, last_verified) for zero-credit token state storage
- Implement OAuth refresh logic that reads refresh tokens and mints fresh access tokens per service, updating token_expiry
- Add per-service health-check calls (Drive files.list, Calendar calendarList.list, Gmail profile.get, Sheets spreadsheets.get, Tasks tasklists.list, Search Console sites.list) to confirm live connectivity
- Wire connector status into the Discover layer data-source registry so downstream intelligence gathering can query available Google sources
- Expose a `verifyAll` action that returns per-service connectivity status and persists results to `google_connectors.status`
- Log each verification run to DeepRun for replayable audit trail
- Add Vercel Cron heartbeat entry to re-verify and refresh tokens every 30 minutes

## Acceptance Criteria
Calling googleConnectorManager with action=verifyAll returns status 'connected' for all six services (Drive, Calendar, Gmail, Sheets, Tasks, Search Console), the google_connectors Supabase table shows fresh non-expired tokens and last_verified timestamps within the last run, a DeepRun log entry exists for the verification, and the Discover layer registry lists all six as available data sources.
