## Summary
Build a unified Google Workspace connector service that validates and health-checks the authorized Drive, Calendar, Gmail, Sheets, Tasks, and Search Console integrations so the Discover layer can reliably pull data.

## Steps
- Create a Base44 backend function `googleConnectorHealth` (Deno/TypeScript) that loads stored OAuth credentials for each Google service from Supabase secrets.
- For each service (Drive, Calendar, Gmail, Sheets, Tasks, Search Console), perform a lightweight authenticated read call to confirm the token scope and validity.
- Implement automatic token refresh using the stored refresh_token when a 401 is returned, persisting the new access_token back to Supabase.
- Normalize each service's status into a GoogleConnector entity record (service, status, scopes, last_checked, error) using Base44 entities.
- Expose the aggregated health report to the Discover layer's data-source registry so downstream intelligence functions can query connector availability.
- Add a Vercel Cron heartbeat entry to invoke `googleConnectorHealth` hourly for continuous monitoring.
- Log all check runs to DeepRun for replayability and surface failures to the Council/Understand layer.

## Acceptance Criteria
Invoking googleConnectorHealth returns a JSON report where all six Google services (Drive, Calendar, Gmail, Sheets, Tasks, Search Console) report status 'connected' with valid non-expired tokens; a GoogleConnector entity record is persisted per service with last_checked timestamp; expired tokens are auto-refreshed; and the hourly Vercel Cron job runs without errors as confirmed in DeepRun logs.
