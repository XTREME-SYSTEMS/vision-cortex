## Summary
Build a unified Google Workspace connector health-check and sync orchestrator that validates and registers all six authorized Google services (Drive, Calendar, Gmail, Sheets, Tasks, Search Console) into the Discover layer's data plane.

## Steps
- Create a Base44 backend function `googleConnectorOrchestrator` in Deno/TypeScript that accepts a list of Google service scopes to validate and sync
- For each service (Drive, Calendar, Gmail, Sheets, Tasks, Search Console), perform an OAuth token validity check and refresh if expired using stored Workspace credentials
- Ping each service's canonical health endpoint (Drive files.list, Calendar calendarList, Gmail profile, Sheets spreadsheets.get, Tasks tasklists.list, Search Console sites.list) and record latency + status
- Persist connector status records to a Base44 entity `ConnectorStatus` (fields: service, connected, last_checked, latency_ms, error, scopes)
- Register each healthy connector as a Discover-layer data source so downstream Understand/Predict layers can query it
- Emit a consolidated DeepRun log entry summarizing which of the six connectors are live, degraded, or failed
- Schedule the orchestrator on Vercel Cron heartbeat to re-validate connectors periodically and auto-refresh tokens
- Expose a summary payload for the dashboard showing green/amber/red status per service

## Acceptance Criteria
All six Google services (Drive, Calendar, Gmail, Sheets, Tasks, Search Console) return connected=true in the ConnectorStatus entity after running the function, tokens auto-refresh when expired, a DeepRun log records the consolidated health summary, and the Vercel Cron heartbeat successfully re-validates connectors on schedule without manual intervention.
