## Summary
Verify and harden the authorized Google Workspace connectors (Drive, Calendar, Gmail, Sheets, Tasks, Search Console) into a unified, health-checked ingestion layer feeding the Discover layer.

## Steps
- Enumerate existing OAuth credentials and scopes for each Google service (Drive, Calendar, Gmail, Sheets, Tasks, Search Console) stored in the connector registry
- Implement a token refresh routine that validates and renews OAuth access tokens before expiry, persisting refreshed tokens to Supabase
- Create a health-check probe per connector that performs a minimal read call (e.g., Drive files.list limit=1, Calendar calendarList, Gmail profile, Sheets metadata, Tasks tasklists, Search Console sites.list)
- Normalize each connector's health result into a ConnectorStatus entity (service, connected boolean, scopes, last_checked, error)
- Wire connector outputs into the Discover layer data source manifest so downstream intelligence gathering can consume them
- Add structured logging and alerting for any connector returning an unauthorized or error state
- Schedule the health-check via Vercel Cron heartbeat to run periodically for continuous validation

## Acceptance Criteria
All six Google connectors (Drive, Calendar, Gmail, Sheets, Tasks, Search Console) return connected=true with valid non-expired tokens; each has a ConnectorStatus record updated within the last cron cycle; the Discover layer manifest lists all six as active data sources; and any failure produces a logged alert with actionable error detail.
