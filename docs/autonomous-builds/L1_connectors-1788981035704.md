## Summary
Build a unified Google Workspace connector service that verifies and persists OAuth authorization for Drive, Calendar, Gmail, Sheets, Tasks, and Search Console into the Discover layer's data plane.

## Steps
- Create a Base44 backend function `googleConnectorSync` (Deno/TypeScript) that centralizes Google Workspace OAuth token management using @/ alias imports
- Define a Supabase table `google_connections` (columns: id, service, oauth_scope, access_token_ref, refresh_token_ref, status, connected_at, last_verified_at) for zero-credit storage of connector state
- Implement per-service health checks: Drive (files.list ping), Calendar (calendarList.list), Gmail (users.getProfile), Sheets (spreadsheets metadata read), Tasks (tasklists.list), Search Console (sites.list)
- Store/refresh OAuth tokens via secure token refs, rotating refresh tokens when access tokens expire
- Register each verified connector as an authorized Discover-layer data source in the system architecture registry
- Emit a DeepRun execution log entry recording verification results, scores, and persisted status for replayability
- Expose a status endpoint returning connection health for all six services to the Council/Understand layer

## Acceptance Criteria
All six Google services (Drive, Calendar, Gmail, Sheets, Tasks, Search Console) report status='connected' in the google_connections table with a recent last_verified_at, each health check returns HTTP 200, a DeepRun log entry is persisted, and the status endpoint returns 6/6 healthy connectors registered as Discover-layer data sources.
