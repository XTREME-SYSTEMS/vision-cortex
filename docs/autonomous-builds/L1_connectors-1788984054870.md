## Summary
Build a unified Google Workspace connector service that validates and health-checks the authorized Drive, Calendar, Gmail, Sheets, Tasks, and Search Console integrations for the Discover layer.

## Steps
- Create a Base44 backend function `googleConnectorHealthCheck` in Deno/TypeScript that reads stored OAuth credentials for the Google Workspace integration
- For each service (Drive, Calendar, Gmail, Sheets, Tasks, Search Console) issue a lightweight authenticated probe call (e.g. Drive files.list?pageSize=1, Calendar calendarList.list, Gmail users.getProfile, Sheets spreadsheets metadata, Tasks tasklists.list, Search Console sites.list)
- Refresh the OAuth access token via the refresh_token grant if a probe returns 401, then retry once
- Persist a ConnectorStatus entity record per service with fields: service, status (connected|degraded|failed), scopes, last_checked, latency_ms, error
- Expose an aggregated response summarizing overall connector health and any missing scopes
- Wire this function into the Discover-layer data-source registry so downstream intelligence gathering can query connector availability
- Schedule a Vercel Cron heartbeat to invoke the health check periodically and alert on failures

## Acceptance Criteria
Invoking googleConnectorHealthCheck returns status 'connected' for all six Google services (Drive, Calendar, Gmail, Sheets, Tasks, Search Console) with valid scopes, each ConnectorStatus entity is persisted with a recent last_checked timestamp, token refresh succeeds on expiry, and the aggregated overall_health field reads 'healthy'.
