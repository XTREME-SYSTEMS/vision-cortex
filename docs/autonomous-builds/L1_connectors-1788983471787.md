## Summary
Build a unified Google Workspace connector health-check and status registry that verifies and persists connection state for Drive, Calendar, Gmail, Sheets, Tasks, and Search Console.

## Steps
- Create a Base44 backend function `verifyGoogleConnectors` (Deno/TypeScript) that iterates over the six Google services (Drive, Calendar, Gmail, Sheets, Tasks, Search Console).
- For each service, perform a lightweight authenticated read call (e.g. Drive files.list?pageSize=1, Calendar calendarList.list, Gmail profile.get, Sheets spreadsheets.get on a probe sheet, Tasks tasklists.list, Search Console sites.list) using stored OAuth credentials.
- Capture per-service status: connected boolean, scopes granted, token expiry, last-checked timestamp, and any error message.
- Upsert results into a `ConnectorStatus` Supabase table (service, status, scopes, expires_at, last_checked, error) for zero-credit persistence.
- Refresh OAuth tokens automatically when expiry is within 5 minutes and re-run the failing probe.
- Return a consolidated report object listing each service and its health, plus an overall `all_connected` flag.
- Register the function to be invoked by Vercel Cron heartbeat on an hourly schedule for continuous monitoring.
- Expose the ConnectorStatus data to the Discover layer so downstream intelligence gathering can gate on connector availability.

## Acceptance Criteria
Invoking verifyGoogleConnectors returns a report where all six services (Drive, Calendar, Gmail, Sheets, Tasks, Search Console) show status 'connected' with valid non-expired tokens, the ConnectorStatus Supabase table is populated with fresh last_checked timestamps, all_connected is true, and the hourly Vercel Cron job successfully re-runs the check without errors.
