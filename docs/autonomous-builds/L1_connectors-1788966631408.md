## Summary
Build a unified Google Workspace connector health-check and orchestration layer that validates and registers the authorized Drive, Calendar, Gmail, Sheets, Tasks, and Search Console connections into the Discover layer.

## Steps
- Create a Base44 backend function `googleConnectorSync` in Deno/TypeScript that centralizes OAuth token retrieval and refresh for all six Google services.
- Implement per-service health probes: Drive (files.list), Calendar (calendarList.list), Gmail (users.getProfile), Sheets (spreadsheets.get on a test sheet), Tasks (tasklists.list), Search Console (sites.list).
- Persist connector status, scopes, token expiry, and last-checked timestamp into a Supabase table `google_connectors` for zero-credit reads.
- Register each healthy connector as a Discover-layer data source per the Intelligence Gathering Protocol, tagging Search Console for SEO intel and Drive for document storage.
- Add automatic token refresh with exponential backoff and mark connectors as degraded/failed on repeated auth errors.
- Expose a summary result and wire the function into the Vercel Cron heartbeat for periodic re-validation.
- Emit a DeepRun log entry recording the validation outcome for replayability.

## Acceptance Criteria
Invoking googleConnectorSync returns status 'connected' for all six services (Drive, Calendar, Gmail, Sheets, Tasks, Search Console), the Supabase `google_connectors` table reflects current token expiry and last-checked timestamps, each connector is registered as a Discover-layer data source, and a DeepRun log entry is persisted; degraded connectors are flagged rather than crashing the run.
