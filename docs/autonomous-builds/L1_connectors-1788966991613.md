## Summary
Build a unified Google Workspace connector service that verifies and persists OAuth authorization for Drive, Calendar, Gmail, Sheets, Tasks, and Search Console, exposing a health-checked interface for downstream Discover-layer functions.

## Steps
- Create a GoogleConnector Base44 entity to persist per-service connection state (service name, scopes, token status, last_verified_at, health).
- Implement OAuth token retrieval and refresh logic using the stored Google Workspace credentials, handling expiry and re-consent flows.
- For each service (Drive, Calendar, Gmail, Sheets, Tasks, Search Console) issue a lightweight verification API call (e.g. Drive files.list?pageSize=1, Calendar calendarList.list, Gmail users.getProfile, Sheets spreadsheets metadata ping, Tasks tasklists.list, Search Console sites.list).
- Record each verification result and scope coverage into the GoogleConnector entity, marking health as connected/degraded/failed.
- Expose a getConnectorStatus read path so Discover-layer functions can query which Google services are live before use.
- Log the verification run to DeepRun for replayability and emit a summary of connected services.
- Add error handling and retry with backoff for transient Google API failures; surface auth failures as actionable re-consent prompts.

## Acceptance Criteria
Invoking syncGoogleConnectors returns health=connected for all six services (Drive, Calendar, Gmail, Sheets, Tasks, Search Console), each with a successful verification API call and non-null last_verified_at persisted in the GoogleConnector entity, and getConnectorStatus reflects the same live state with a corresponding DeepRun log entry.
