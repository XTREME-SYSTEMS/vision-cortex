## Summary
Build a unified Google Workspace connector health-check and token-refresh module that verifies and maintains authorized access to Drive, Calendar, Gmail, Sheets, Tasks, and Search Console.

## Steps
- Create a Base44 backend function `googleConnectorManager` in Deno/TypeScript that centralizes OAuth token storage and refresh for all six Google services
- Store per-service OAuth credentials and refresh tokens in Supabase table `google_connectors` (service, access_token, refresh_token, expires_at, scopes, status)
- Implement token-refresh logic: on each invocation, check expiry and refresh via Google OAuth token endpoint when within 5 minutes of expiration
- Add per-service health probes: Drive (files.list limit 1), Calendar (calendarList.list), Gmail (users.getProfile), Sheets (spreadsheets.get on a probe sheet), Tasks (tasklists.list), Search Console (sites.list)
- Return a normalized status report per service (connected | expired | error) with last-checked timestamp and scope validation
- Persist health results to Supabase `google_connectors` and emit a DeepRun execution log entry for replayability
- Expose a mode param (`verify` | `refresh` | `full`) so the connector can be called by Vercel Cron heartbeat for autonomous monitoring
- Wire this into the Discover layer data-source registry so downstream functions can query connector availability before use

## Acceptance Criteria
Invoking googleConnectorManager with mode 'full' returns status 'connected' for all six services (Drive, Calendar, Gmail, Sheets, Tasks, Search Console), refreshes any near-expiry tokens successfully, persists results to the Supabase google_connectors table, and writes a DeepRun log entry; a subsequent verify call within the token window returns cached healthy status without re-authenticating.
