## Summary
Build a unified Google Workspace connector service that verifies and persists OAuth authorization state for Drive, Calendar, Gmail, Sheets, Tasks, and Search Console so downstream Discover-layer functions can consume them.

## Steps
- Define a GoogleConnector Base44 entity with fields: service_name, scopes, status, token_ref, last_verified_at, health.
- Create a backend function that reads stored OAuth credentials from Supabase (zero-credit store) for each Google service.
- For each service, perform a lightweight authenticated ping (Drive files.list?pageSize=1, Calendar calendarList, Gmail getProfile, Sheets spreadsheets metadata, Tasks tasklists.list, Search Console sites.list) to validate scopes and token freshness.
- Refresh expired access tokens via the stored refresh_token and Google OAuth token endpoint; persist new tokens to Supabase.
- Upsert one GoogleConnector row per service with status (connected|degraded|failed), granted scopes, and last_verified_at timestamp.
- Emit a consolidated connector-health summary to CoreDocument/architecture Data Plane and log a DeepRun execution record.
- Expose the health summary so Discover-layer functions can gate on connector availability.

## Acceptance Criteria
Invoking connectGoogleWorkspace returns status connected for all six services (Drive, Calendar, Gmail, Sheets, Tasks, Search Console), six GoogleConnector entity rows exist with recent last_verified_at and valid granted scopes, expired tokens are auto-refreshed and persisted to Supabase, and a DeepRun log records the successful verification run with no failed connectors.
