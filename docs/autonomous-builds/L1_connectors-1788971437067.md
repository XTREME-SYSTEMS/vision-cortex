## Summary
Build a unified Google Workspace connector service that verifies, persists, and health-checks OAuth authorizations for Drive, Calendar, Gmail, Sheets, Tasks, and Search Console.

## Steps
- Define a GoogleConnector Base44 entity with fields: service_name, oauth_status, scopes[], token_ref, last_verified_at, health_status
- Register OAuth scopes for all six services (drive.readonly, calendar, gmail.readonly, spreadsheets, tasks, webmasters.readonly) in the Google Workspace integration config
- Implement token exchange and secure refresh-token storage in Supabase (zero-credit external store) referenced by token_ref
- For each service, invoke a lightweight test API call (Drive files.list limit 1, Calendar calendarList, Gmail profile, Sheets metadata, Tasks tasklists, Search Console sites.list) to confirm live connectivity
- Persist per-service health_status and last_verified_at, mark oauth_status='connected' only on successful test call
- Expose results to the Discover layer data-source registry so downstream state machines can consume the connectors
- Schedule a Vercel cron heartbeat to re-verify token health and auto-refresh expiring tokens

## Acceptance Criteria
All six GoogleConnector records exist with oauth_status='connected' and health_status='healthy', each backed by a successful live test API call, refresh tokens stored in Supabase, and the cron heartbeat re-verifies health without manual intervention.
