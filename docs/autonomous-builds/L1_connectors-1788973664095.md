## Summary
Build a unified Google Workspace connector service that validates and health-checks the authorized Drive, Calendar, Gmail, Sheets, Tasks, and Search Console integrations for the Discover layer.

## Steps
- Create a Base44 backend function `googleConnectorHealth` in Deno/TypeScript that iterates over each authorized Google service (Drive, Calendar, Gmail, Sheets, Tasks, Search Console)
- Load OAuth credentials/refresh tokens from the secure Base44 secrets store and refresh access tokens as needed
- For each service, issue a minimal read-only probe call (Drive: files.list limit 1; Calendar: calendarList.list; Gmail: users.getProfile; Sheets: spreadsheets metadata ping; Tasks: tasklists.list; Search Console: sites.list)
- Record per-service status (connected/degraded/failed), latency, scopes granted, and last-checked timestamp into a Supabase table `google_connector_status` for zero-credit persistence
- Emit a consolidated ConnectorHealth entity into Base44 with an overall health score and any remediation flags for missing scopes
- Register the function on a Vercel Cron heartbeat to re-validate connectors every 6 hours and alert the Discover layer on any failure
- Expose the aggregated status to the Discover layer data-source registry so intelligence gathering can rely on live connectors

## Acceptance Criteria
Function returns HTTP 200 with a JSON report listing all six Google services each marked 'connected', writes a fresh row to Supabase `google_connector_status`, persists a ConnectorHealth entity with overallScore >= 0.9, and the Vercel Cron job successfully re-runs the check on schedule without credit-consuming operations.
