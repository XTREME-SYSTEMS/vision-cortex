## Summary
Build a unified Google Workspace connector service that validates and health-checks the authorized Drive, Calendar, Gmail, Sheets, Tasks, and Search Console integrations, persisting connection state for the Discover layer.

## Steps
- Create a Base44 backend function 'googleConnectorManager' (Deno/TypeScript) that centralizes OAuth token retrieval and refresh for all six Google services.
- Define a Supabase table 'google_connections' storing service name, scope, token status, last_verified_at, and health flag for zero-credit state reads.
- Implement per-service health-check calls: Drive files.list(pageSize=1), Calendar calendarList.list, Gmail users.getProfile, Sheets spreadsheets metadata ping, Tasks tasklists.list, Search Console sites.list.
- Add token refresh logic using stored refresh tokens; on 401, refresh and retry once, then mark service degraded if still failing.
- Expose the aggregated connection status to the Discover layer as a data source registry entry consistent with the intelligence_protocol Data Sources list.
- Emit a DeepRun log entry recording the verification run, per-service status, and any remediation actions taken.
- Wire a Vercel Cron heartbeat to invoke the connector health-check on a recurring interval for autonomous re-validation.

## Acceptance Criteria
Invoking googleConnectorManager returns a JSON status object listing all six services (Drive, Calendar, Gmail, Sheets, Tasks, Search Console) each with status 'connected', a fresh last_verified_at timestamp is written to the google_connections Supabase table, expired tokens are auto-refreshed, and a DeepRun log entry is persisted for the verification run.
