## Summary
Build a unified Google Workspace connector service that validates and health-checks the authorized Drive, Calendar, Gmail, Sheets, Tasks, and Search Console integrations, persisting their status for downstream Discover-layer consumption.

## Steps
- Create a Base44 backend function `googleConnectorHealthCheck` that iterates over the six authorized Google services (Drive, Calendar, Gmail, Sheets, Tasks, Search Console).
- For each service, perform a lightweight read call (e.g., Drive files.list limit 1, Calendar calendarList, Gmail profile, Sheets metadata get, Tasks tasklists.list, Search Console sites.list) using stored OAuth tokens.
- Implement automatic token-refresh logic: on 401, use the refresh_token to obtain a new access_token and persist it to the credentials store.
- Define/upsert a Base44 entity `GoogleConnector` with fields: service, status (connected|degraded|failed), scopes, last_checked, last_error, token_expiry.
- Persist each service's health result to the `GoogleConnector` entity after every check.
- Register a Vercel Cron heartbeat to invoke `googleConnectorHealthCheck` every 30 minutes for continuous monitoring.
- Expose the aggregated connector status to the Discover layer so scraping/search flows can gate on connector availability.
- Emit a DeepRun log entry recording the check outcome for replayability.

## Acceptance Criteria
Invoking googleConnectorHealthCheck returns status 'connected' for all six Google services, upserts corresponding GoogleConnector entity rows with fresh last_checked timestamps and valid (non-expired) tokens, expired tokens are auto-refreshed, and the Vercel Cron heartbeat successfully triggers the check on schedule with a DeepRun log entry persisted.
