## Summary
Build a unified Google Workspace connector health-check and orchestration function that verifies and normalizes access to Drive, Calendar, Gmail, Sheets, Tasks, and Search Console for the Discover layer.

## Steps
- Enumerate the authorized Google services (Drive, Calendar, Gmail, Sheets, Tasks, Search Console) and confirm OAuth scopes/tokens are stored in Supabase connector registry
- Create a Base44 backend function that validates each connector by issuing a lightweight read call (Drive files.list, Calendar calendarList, Gmail profile, Sheets metadata, Tasks tasklists, Search Console sites.list)
- Normalize each result into a standard ConnectorStatus record {service, connected, scopes, lastCheck, latencyMs, error}
- Persist ConnectorStatus records to a Base44 entity and mirror to Supabase for zero-credit reads
- Register the connectors as Discover-layer data sources in the intelligence protocol config so downstream layers can query them
- Add automatic token-refresh handling and surface any re-auth-required services in the response
- Wire the health-check into the Vercel cron heartbeat for periodic revalidation
- Return an aggregate report with overall_health and per-service detail

## Acceptance Criteria
Invoking syncGoogleWorkspaceConnectors returns connected:true for all six services (Drive, Calendar, Gmail, Sheets, Tasks, Search Console) with valid scopes and non-null lastCheck timestamps, ConnectorStatus records are persisted to Base44 and Supabase, any expired tokens are auto-refreshed or flagged as re-auth-required, and the connectors appear as active Discover-layer data sources queryable by downstream layers.
