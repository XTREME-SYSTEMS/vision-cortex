## Summary
Build a unified Google Workspace connector service that verifies and manages OAuth connections for Drive, Calendar, Gmail, Sheets, Tasks, and Search Console within the Discover layer.

## Steps
- Create a Base44 backend function `googleConnectorManager` in Deno/TypeScript that centralizes OAuth token handling for all six Google services
- Store and refresh OAuth tokens securely in Supabase (table `google_connections` with columns: service, access_token, refresh_token, expires_at, scopes, status)
- Implement per-service scope validation: Drive (drive.readonly/file), Calendar (calendar), Gmail (gmail.readonly/send), Sheets (spreadsheets), Tasks (tasks), Search Console (webmasters.readonly)
- Add a health-check routine that pings each service's lightweight endpoint (e.g. Drive about.get, Calendar calendarList, Gmail profile, Sheets metadata, Tasks tasklists, Search Console sites.list) and records connection status
- Implement automatic token refresh when expires_at is within 5 minutes and update Supabase
- Expose a `verify` action returning per-service connected/disconnected state for the Discover layer to consume
- Log connection events to DeepRun for replayability and register the connector spec in DeepSpec
- Wire the connector into the Discover layer data-source registry so downstream intelligence gathering can query authorized Google services

## Acceptance Criteria
Invoking googleConnectorManager with action 'verify' returns status 'connected' for all six services (Drive, Calendar, Gmail, Sheets, Tasks, Search Console); tokens auto-refresh before expiry; each service passes its live health-check ping; connection state is persisted in the Supabase google_connections table and events are logged to DeepRun.
