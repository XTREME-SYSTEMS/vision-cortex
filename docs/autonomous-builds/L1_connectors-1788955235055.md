## Summary
Build a unified Google Workspace connector service that validates and health-checks the authorized Drive, Calendar, Gmail, Sheets, Tasks, and Search Console integrations, persisting their status to the Discover layer.

## Steps
- Create a Base44 backend function `googleConnectorHealth` that reads stored OAuth credentials for each Google service from Supabase secrets/config
- For each service (Drive, Calendar, Gmail, Sheets, Tasks, Search Console), perform a lightweight read call to verify token validity and scope coverage
- Implement automatic token refresh using the stored refresh_token when an access token is expired or returns 401
- Normalize each service result into a status record: {service, connected, scopes, last_checked, error}
- Persist the aggregated connector status to a Base44 entity `ConnectorStatus` and mirror to Supabase for zero-credit reads
- Expose the health summary to the Discover layer so downstream state machines can gate on connector availability
- Add a Vercel Cron heartbeat entry to invoke `googleConnectorHealth` on a recurring schedule for continuous monitoring
- Log each run to DeepRun for replayability and emit alerts on any degraded/disconnected service

## Acceptance Criteria
Invoking googleConnectorHealth returns a status array with all six Google services marked connected:true with valid scopes; a ConnectorStatus record is persisted with a fresh last_checked timestamp; expired tokens are auto-refreshed successfully; and the Vercel Cron heartbeat re-runs the check on schedule with results logged to DeepRun.
