## Summary
Build a unified Google Workspace connector service that validates OAuth credentials and exposes read/write operations for Drive, Calendar, Gmail, Sheets, Tasks, and Search Console.

## Steps
- Create a backend function `googleConnectorSync` in the Base44 Deno/TypeScript backend that centralizes Google OAuth token management (refresh, scope validation, expiry handling).
- Define a Supabase table `google_connections` to store per-service connection status, granted scopes, token expiry, and last-sync timestamp for zero-credit reads.
- Implement per-service client adapters (Drive, Calendar, Gmail, Sheets, Tasks, Search Console) each with a standard interface: `verify()`, `read(params)`, `write(params)`.
- Wire scope verification: on invocation, confirm the OAuth token carries the required scope for each requested service and mark unauthorized services in the response.
- Add a heartbeat entry via Vercel Cron to periodically call `googleConnectorSync` with `mode:'verify'` to keep tokens fresh and connection health current.
- Persist a DeepRun log entry recording which connectors were validated, their status, and any errors, replayable per DEEP protocol.
- Expose connection status to the Discover layer so Search Console and Drive data feed the intelligence pipeline.
- Add error handling and ret/backoff for revoked or expired tokens, surfacing a re-auth flag in `google_connections`.

## Acceptance Criteria
Invoking googleConnectorSync returns a status object listing all six services (Drive, Calendar, Gmail, Sheets, Tasks, Search Console) each marked 'connected' with valid non-expired scopes; the google_connections table reflects current status; a DeepRun log entry is persisted; and a test read from Search Console and Drive returns live data without credit consumption.
